# Шёпот — статический сайт + Supabase (без сервера!)

Сайт собран в статику: папку `out` (или этот zip) можно положить на ЛЮБОЙ
хостинг — сервер не нужен вообще. Весь бэкенд работает в облаке Supabase.

Публичный ключ уже вшит в сборку — ничего дополнительно настраивать не нужно.

| Что | Где |
|---|---|
| Регистрация/вход (ник + пароль) | Supabase Auth (почта автоподтверждается триггером) |
| Профили, чаты, рулетка, друзья | Supabase Postgres + RLS |
| Живые сообщения, «печатает…», presence | Supabase Realtime |
| Музыка и аватарки | Supabase Storage |

## Хостинг из России (Netlify/Vercel из РФ часто недоступны)

### Вариант 1 — Timeweb Cloud (самый простой, с HTTPS сразу)
1. Зарегистрируйтесь на timeweb.cloud
2. Панель → «Приложения» → Создать → «Статичный сайт» (Frontend-приложение)
3. Загрузите этот zip (или содержимое папки out)
4. Сайт получит адрес вида `*.twc1.net` с HTTPS — PWA и service worker работают
5. Цена: ~200–300 ₽/мес (для статики это с запасом)

### Вариант 2 — Beget (классический хостинг)
1. beget.com → виртуальный хостинг (есть тестовый период)
2. В файловый менеджер откройте `site.ru/public_html` (ваш технический домен)
3. Залейте содержимое папки out внутрь (index.html должен лежать в корне)
4. Технический домен вида `логин.beget.tech` выдаётся бесплатно, с HTTPS

### Вариант 3 — Yandex Object Storage (почти бесплатно)
1. console.yandex.cloud → Object Storage → создать бакет, например `shpot`
2. Загрузите содержимое out (кнопка «Загрузить объекты»)
3. Вкладка бакета «Веб-сайт» → включить «Хостинг статического сайта»,
   индексная страница: index.html
4. Адрес сайта появится в панели (`<бакет>.website.yandexcloud.net`)
5. Нюанс: на стандартном адресе может не быть HTTPS — тогда привяжите свой
   домен + бесплатный сертификат Yandex Certificate Manager.
   Без HTTPS чат работает, но PWA-установка/offline — нет.
6. Цена: копейки за гигабайты трафика

### Вариант 4 — GitVerse Pages (БЕСПЛАТНО, российский)
1. gitverse.ru → регистрация (бесплатно)
2. Создать публичный репозиторий, например `shpot`
3. Загрузить туда содержимое папки out (через веб-интерфейс: Add file → Upload files)
4. В настройках репозитория включить Pages
5. Получите бесплатный адрес вида `*.pages.gitverse.ru`

### Вариант 5 — GitHub Pages (бесплатно, но из РФ нестабилен)
1. github.com → новый репозиторий → Upload files → залить содержимое out
2. Settings → Pages → Deploy from branch → main / (root)
3. Адрес: `логин.github.io/имя-репо`
Нюанс: github.io у некоторых провайдеров РФ открывается плохо.

### Свои домены
Если есть домен (reg.ru, nic.ru и т.п.), привяжите его к любому варианту выше.

⚠️ Netlify / Vercel / Cloudflare Pages из РФ часто недоступны (блокировки CDN,
ECH) — если «сайт не открывается», дело в этом, а не в сборке.

## Безопасность
- В клиенте только ПУБЛИЧНЫЙ publishable-ключ — это нормально и так задумано.
- Все данные защищены RLS-политиками Supabase (каждый видит только своё).
- Секретный ключ (`sb_secret_…`) НИКУДА не зашит — держите его в тайне и
  используйте только для админ-скриптов на своей стороне.

## Полезное
- Схема БД, RLS и RPC: `scripts/supabase-setup.sql` в проекте (идемпотентный).
- Ник `ceo_twiin` свободен — при регистрации он получает бейдж «Создатель».
